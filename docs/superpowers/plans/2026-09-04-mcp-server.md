# Lause DS — Plan 5: The MCP Server and the Agent-Ready Files

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An AI tool asks the system for its parts and builds a correct screen. `packages/mcp` is a Model Context Protocol server with four tools — `list_tokens`, `list_components`, `get_component`, `check_usage` — that runs locally over stdio (`npx lause-ds-mcp`) and on a URL as one Netlify Function; the files it serves ship regardless of the server: `tokens/*.tokens.json`, `components.manifest.json`, `llms.txt`.

**Architecture:** One data layer, two transports. A generator reads the code (each component's props and JSDoc through the TypeScript compiler), the stories (the states shown), the token outputs, the Figma ledger (set ids and source paths) and the spec (proof screens, usage rules), and writes `components.manifest.json` and `llms.txt` at the repo root; CI fails if they drift. The four tools are pure functions over that data with an in-memory test client. The stdio entry and the Netlify function both call the same `buildServer()`. The Netlify site is git-connected and deploys on merge; the docs site (Plan 6) will share it.

**Tech Stack:** `@modelcontextprotocol/sdk` 1.30, `zod` 4.5, TypeScript 7 (compiler API for the manifest), vitest, `@netlify/functions` 6, Netlify Functions v2 with the SDK's web-standard Streamable HTTP transport.

**Spec:** `docs/specs/2026-09-03-lause-ds-design.md` — §2 decisions 1, 9, 10; §6 MCP server; §4 proof screens. Figma mapping: `figma/library.json`.

**Roadmap:** Plan 6 docs site and public Storybook on the same Netlify site.

## Global Constraints

- Node `24`, npm workspaces, TypeScript strict, ESM only. New workspace `packages/mcp`, package name `lause-ds-mcp`, published (not private), with a `bin` of the same name.
- The server never invents data: every answer comes from the generated files. `components.manifest.json` and `llms.txt` are generated by `npm run build:manifest`, committed, and covered by CI's drift check like the token outputs.
- Tools are read-only. The hosted endpoint is public, rate-limited, CORS-open for `POST`/`OPTIONS`, no secret — it is a portfolio demo of read-only data (ruling; a bearer token can be added later per the netlify-mcp-servers skill).
- Tool descriptions are written for an agent: what it returns, when to use it. Docs in English; sample copy Estonian.
- Netlify: read env with `Netlify.env.get`, `.netlify/` git-ignored, no secrets in code. The site must be connected to the GitHub repo (deploy previews per PR, deploy on merge). Connecting needs Rock's GitHub authorisation in Netlify; the plan stops there and says so.
- Commit messages conventional, each ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; PR body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

- [ ] **Step 2: Implement the generator**

`packages/mcp/src/manifest.ts` — with the `typescript` package (root devDependency; import `typescript` as `ts`):
1. Create a `ts.Program` over `packages/ui/src/index.ts` with the ui `tsconfig.json` options (`ts.getParsedCommandLineOfConfigFile`). From the checker, take `getExportsOfModule` of `index.ts`; keep value exports whose declaration is a function (components: name starts uppercase; hooks: starts with `use`).
2. For each: `source` = the declaring file relative to root; `summary` = the JSDoc comment on the function (`symbol.getDocumentationComment(checker)`); `props` = properties of the first parameter's type — for each property: `name`, `type` = `checker.typeToString` of the property type with `NonNullable` applied when optional (so `'filled' | 'outline' | 'dim'` not `… | undefined`), `required` = not optional, `doc` = its JSDoc, `default` = read from the function's destructuring pattern (`variant = 'filled'`) by walking the parameter's `ObjectBindingPattern` initialisers and printing them with `node.getText()`. Skip properties inherited from `ComponentProps<'x'>` (keep only those declared in the file — check `declaration.getSourceFile()` equals the component's file). For hooks, `props` = the options object the same way, `states` = [].
3. `states` = the story file's named exports in order (parse `<Name>.stories.tsx` with `ts.createSourceFile`, collect `export const X`), `[]` when no story file.
4. `figma` from `figma/library.json` `components[name]` (`setId` or `componentId`, plus `fileUrl`); `proofScreen` from a table in the generator copied from spec §4 (`Sentence: Lugeja`, `Bubble: Lugeja, ⌥ held`, `Dial: Lugeja, Skeemid`, `Keycap: Everywhere`, `Button: Everywhere`, `Tile: Eksam, Kordamine, Koosta`, `Progress: Everywhere`, `Bar: Täna, tulemus`, `Cell: Õigused`, `Nav: Everywhere`, `TileStack: Eksam`, `CellGrid: Õigused`, `usePeek: Lugeja`).
5. `rules` per component: a table in the generator (English), e.g. Button `['Every control shows its key: pass keycap whenever there is one.', 'filled is the one primary action on a screen.', 'Disabled controls never hover.']`; Tile `['Options stack vertically in a TileStack, never in a row, except the two of a true/false item.', 'Options run to 40 characters.']`; Sentence `['The English pair (text + note) is required together: the note says the translation is unofficial.', 'Term ids that repeat pin together.']`; Nav `['Chrome stays Estonian; while peeking it swaps to English and never gains a subtitle.']`; Cell `['Rows Igaüks / Eesti kodanik, columns Tohib piirata / Ei tohi piirata; keys 1–4.']`; Bubble `['Sits above its word; the count is decorative to assistive technology.']`; Dial `['The exam disables it as one control.']`; Progress/Bar `['One segment per unit; the counts are given in words.']`; others `[]`. System `rules`: `['Use only token utilities: the Tailwind theme is closed, so bg-red-500 or p-11 do not exist.', 'Two fonts only: font-content (Young Serif) for what is being learned, font-chrome (Instrument Sans) for the app.', 'Type is used through the six roles (label, body, title, reading, headline, display), never a size number.', 'Contrast is a gate: every text pair 4.5:1, every graphic pair 3:1, in both modes.', 'Hit targets are at least 44px.', 'Every interactive element has a visible focus ring; disabled never hovers.']`.
6. `generatedFrom.commit` = `git rev-parse --short HEAD` (skip in tests by comparing everything except `generatedFrom`; adjust the drift test to `expect({...file, generatedFrom: undefined}).toEqual({...manifest, generatedFrom: undefined})`).
7. `renderLlms(manifest, data)`: Markdown-ish text: `# Lause design system`, one paragraph, `## Tokens` with every semantic token as `name: light · dark — description`, `## Components` with `## <Name>` sections (summary, props table one line per prop, states, rules, source, Figma link), `## Rules`. Deterministic ordering.
8. CLI: when run directly, write `components.manifest.json` (2-space JSON + newline) and `llms.txt` at the repo root and print the paths.

### Task 4: check_usage

**Files:**
- Create: `packages/mcp/src/check-usage.ts`, `packages/mcp/test/check-usage.test.ts`
- Modify: `packages/mcp/src/server.ts` (register the tool)

**Interfaces:**
- Produces: `checkUsage(data, code: string): { findings: Finding[] }`, `Finding = { rule: string; line: number; excerpt: string; message: string; fix?: string }`.

Rules, each with one positive and one negative test case:
1. `raw-hex`: a hex colour literal (`#[0-9a-f]{3,8}` outside a comment) → "Use a semantic colour token (bg-ink, text-dim, …)".
2. `raw-font`: `font-family:` or a font name (`Young Serif`, `Instrument Sans`, `Inter`, `Georgia`, `Arial`, `system-ui`) in a class or style → "Use font-content or font-chrome".
3. `off-theme-utility`: a Tailwind class whose theme namespace is closed but whose key is not in `theme.css` — build the allowed set from `packages/ui/src/tokens/theme.css` (`--color-*`, `--spacing-*`, `--text-*` roles, `--font-*`, `--radius-*`, `--shadow-*`, `--leading-*`, `--tracking-*`) and flag `bg-red-500`, `p-11`, `text-sm`, `rounded-lg`, `shadow-md`, `font-sans`, `leading-tight` when the key is absent; arbitrary values `[…]` and `(--…)` pass; `min-h-[44px]` and `max-w-[640px]`/`[1020px]` pass; other `[Npx]` sizes flag as `raw-size`.
4. `tile-in-row`: a `<Tile` inside an element with `flex-row` or `grid-cols-` whose Tile count is 3 or more → "Options stack in a TileStack; only the two of a true/false item sit side by side".
5. `stem-without-role`: a text-size class or `font-size:` on an element that is not one of the six roles — any `text-[…px]` or `text-xs|sm|base|lg|xl|2xl…` → "Type is used through the roles: text-label, text-body, text-title, text-reading, text-headline, text-display".
6. `focus-missing`: a `<button` or `role="button"` without `focusRing`/`focus-visible:` → "Every interactive element needs the focus ring (import focusRing from lause-ds' styles or use the components)". Skip when the element is one of the system's components.

Implement line by line with regexes; the theme key set is read once from `theme.css`. Register `check_usage` with description: "Checks a snippet of JSX/TSX/CSS against the Lause rules and returns findings with line numbers and fixes: raw hex, raw fonts, Tailwind utilities outside the closed theme, raw sizes, tiles in a row, text sizes outside the six roles, buttons without a focus ring. Empty findings means the snippet follows the system."
