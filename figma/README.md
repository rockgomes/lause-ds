# figma/variables.json

Generated by `@lause-ds/tokens` (`packages/tokens/src/emit-figma.ts`). Do not edit by hand —
it is regenerated by `npm run build:tokens` and CI fails if it drifts.

## Contract

Two collections:

- **Primitives** — one mode, `Value`. Every variable is a literal (colours as hex, dimensions
  as px floats, `type/leading/*` as unitless ratios, font stacks as strings).
- **Semantic** — two modes, `Light` and `Dark`. Every non-typography leaf, and the `fontFamily`
  and `fontSize` fields of a typography role, carry `{ "alias": "<primitive path>" }` rather
  than a resolved value — the semantic variable stays bound to the primitive it points at, in
  both modes, the way the source token JSON does.

## Value shapes

- Colours: hex strings (`"#0f2238"`) on primitives, `{ "alias": "color/navy/900" }` on
  semantics.
- Dimensions (`type/size/*`, `space/*`, `radius/*`): px, as a float.
- `type/leading/*`: unitless ratios (`1.1`–`1.85`). These are **not** for binding to a Figma
  line-height field — Figma line height is pixels, not a ratio.
- `type/<role>/lineHeight`: a computed px float (`round(fontSize × leading)`), meant to be
  bound to a text style's line height directly.
- Shadows (`shadow/*`, `shadow/tile`): one CSS-shorthand string per mode
  (`"0px 6px 18px 0px rgba(15, 34, 56, 0.10)"`), not a Figma effect — there is no per-field
  shadow variable.

## Importing

Names use `/` as the path separator (`color/navy/900`, `type/body/lineHeight`), matching
Figma's variable-group convention. An importer resolves each `{ "alias": "<name>" }` to the
target variable's id by that name. Building Figma variables from this file, and wiring that
resolution, is Plan 3's job — this package only emits the JSON.
