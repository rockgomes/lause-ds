# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder page with the Lause front door: a single-page site built from the system's own components that tells the story, shows one live example per component, switches light and dark, runs the reader's peek gesture in the page, calls the hosted MCP server from the browser, and links to a published Storybook.

**Architecture:** A private workspace `packages/site` (Vite + React 19 + Tailwind 4) that imports `lause-ds` like any consumer and reads the repo's generated data (`tokens/*.tokens.json`, `components.manifest.json`, `figma/library.json`) at build time, so every value on the page comes from the single source. `vite build` writes to the root `site/` folder that Netlify already publishes; `build:site` then adds Storybook under `site/storybook/` and the agent files at the root. The MCP demo posts JSON-RPC to `/mcp`, the Netlify Function that ships in the same deploy. Design frames are made in the Lause Figma file first (Task 1) and Rock approves them before any code.

**Tech Stack:** Vite 8.2.2, `@vitejs/plugin-react` 6.1.1, `@tailwindcss/vite` 4.3.3, React 19.2.8, `lause-ds` (workspace), Vitest 4.1.11 browser mode with `@vitest/browser-playwright` 4.1.11, `vitest-browser-react` 2.3.0, `axe-core` 4.13.0, Storybook 10.6.0 static build, Netlify (site `shiny-frangipane-78fc08`), Figma MCP (`create_new_file`, `use_figma`, `get_screenshot`, `get_libraries`); the library file `Fi9CrQ0KzJdpCuwNcWbZKF` is consumed, never edited.

**Spec:** `docs/specs/2026-09-03-lause-ds-design.md`, decision 7 (custom site as front door built with the system's own components, one example per component, links to Storybook, never copies its job), decision 9 (same host and deploy as the MCP server), §1 (the demo is "an AI builds a correct screen from my system"), §7 (docs in English, app chrome Estonian).

## Global Constraints

- Node `24`, npm workspaces, TypeScript strict, ESM only. New workspace `packages/site`, package name `@lause-ds/site`, `"private": true`, never published, no changeset.
- The site consumes `lause-ds` exactly as the README tells consumers to: `@import 'tailwindcss'; @import 'lause-ds/styles.css'; @source '<path to lause-ds dist>';` in the CSS entry. Site code uses only theme utilities; `npm run build:mcp` then `node -e` with `checkUsage` from `lause-ds-mcp` over every `packages/site/src/**/*.tsx` file must return zero findings (Task 7 automates this as a test).
- The site never hard-codes a token value, a component prop table, or a Figma id: colours, type roles, component summaries, props, proof screens and Figma links are imported from `tokens/semantic.light.tokens.json`, `tokens/semantic.dark.tokens.json`, `tokens/primitives.tokens.json`, `components.manifest.json` and `figma/library.json` at build time.
- Register: committed portfolio front door (Rock, 2026-09-05). Interactive where the product does something; one authored motion moment (the hero); every animation has a `prefers-reduced-motion` fallback; no fabricated numbers or testimonials.
- Design before code: Task 1 produces Figma frames and STOPS for Rock's approval. Tasks 2–8 implement the approved frames. If Rock changes the frames, the change is recorded in the ledger before the affected task runs.
- Verification gates (Rock's UI rules): axe on the whole page in light and dark with zero violations; no horizontal scroll at 320, 390, 768, 1024, 1440 and 1920 px; `:focus-visible`, disabled and loading states on every interactive element; `prefers-reduced-motion` respected.
- Copy: English everywhere on the site, including annotations in Figma. Estonian appears only inside the components' sample content (the reader sentence, the nav labels) because that is the product's language.
- Netlify: `publish = "site"`, functions dir unchanged, no env vars needed. `site/` becomes fully git-ignored (generated).
- Commit messages conventional, each ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`; PR body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

  export type Theme = 'light' | 'dark';
  const KEY = 'lause-theme';
  const listeners = new Set<() => void>();
  function read(): Theme { return document.documentElement.dataset.theme === 'dark' ? 'dark' : 'light'; }
  function write(t: Theme) {
    document.documentElement.dataset.theme = t;
    try { localStorage.setItem(KEY, t); } catch { /* private mode */ }
